## 0. 决策摘要

**一句话**：你只在临海待七天。第八天清晨就走。夜里睡不着，通讯录里有三个人醒着；你只能回拨其中一个。

**五个决定**

1. 做 **7 夜 × 3 条路线 × 10 个结局**的短篇，不做无限陪伴。
2. 用「**通讯录 / 聊天 / 夜终**」三件套，不做微信四页签的二次元皮肤。
3. **六位居民全部重画为二次元形象**；先开放三位完整路线，另外三位做同城配角。
4. **脚本骨架 + AI 自由聊天**：关键台词作者写，日常对话模型接。
5. 试用期**全免费**，不卖好感、不抽卡、不把喜点变成「让 TA 喜欢你」的门票。

**为什么**

- 现有广场有六个人、能聊天、有朋友圈、有礼物回声，但**没有目标、没有进度、没有结束**。聊三句和聊三十句没有区别。
- 《心跳通讯录》证明的不是「像素风好卖」，是**有限结构**好传播：玩家会「打完」、会收集结局、会写攻略。
- 我们已经有 70% 的机器：账号、SSE 聊天、六个人设、DING、朋友圈、礼物、回声、喜点、AI 标、安全边界。缺的是 30%：剧情状态机、作者内容、像素资产、结局收集、夜间外壳。

**成功标准（试用 4 周）**

| 指标 | 目标 |
|---|---|
| 第 1 夜完成率 | ≥ 55% |
| 打完任意结局 | ≥ 25% |
| 夜均用户发言 | ≥ 15 轮 |
| D7 回访 | ≥ 25% |
| 结局卡分享率 | ≥ 8% |
| 严重安全事件 | 0 |

> 分母为完成 18+ 确认的启动用户。「第 1 夜完成率」= 到达第 1 夜夜终卡；「打完」= 到达任意结局；「D7」= 首次启动后第 7 天回访。

**止损线**

- 第 1 夜完成率 < 35%，或打完率 < 10% → 停，不再加内容。
- 出现未成年人 / 色情 / 冒充真人 / 诱导转账任一严重事件 → 立即下线。
- 单条完整路线成本 > ¥5 → 先修成本，不扩量。

**现在要拍板的 5 件事**

1. 名字用《天亮以前》，还是《夜航通讯录》/《未接来电》？
2. 首发 3 条路线，还是 6 条？
3. 关系尺度：心动向（推荐），还是明确恋爱？
4. 独立 TestFlight 包，还是主 App 里的邀请制入口？
5. 试用期是否完全免费（推荐是）？

## 1. 调研：心跳通讯录是什么

### 1.1 能确认的事实

- 它是《原神》「千星奇域」里的**玩家自制关卡**，不是一款独立 App `[资料]`。米游社有条目，好游快爆把它列在「关卡推荐」，B 站实况直接称它「一个作品拓宽了整个千星的可能性」。
- 它被当作 **galgame** 来讨论：有对话、有节点、有结局，玩家会说「打完了」，社区有「结局全收录」「全结局攻略」「节点攻略」`[资料]`。
- 这张图是**像素画风**的封面 / 缩略图，标题就是「通讯录」，画面里是一个猫耳、制服、脸红的女孩 `[资料：封面]`。
- 它按「天」推进：社区有条目叫「第零天到第一天攻略」`[资料，中等置信]`。
- 它不是官方出品，是 UGC；传播发生在原神 / 千星奇域内部，**零安装、可分享** `[资料]`。

### 1.2 不能确认的事

具体几夜、几个角色、几条线、结局叫什么、有没有好感数值、有没有 CG 收集——这些正文（知乎、B 站、米游社、网易社区）在当前网络环境下打不开，只能看到标题与索引。**本稿不编这些细节**；下面的拆解，机制部分标 `[推断]`。

### 1.3 设计拆解：它做对了什么

| # | 设计 | 为什么有效 | 证据 |
|---|---|---|---|
| 1 | **通讯录就是世界观** | 不是「聊天 App 皮肤」，而是「你只能通过手机联系 TA」；通讯录天然有「谁在、谁不在、谁没接」 | 标题 + 封面 `[资料]` |
| 2 | **像素画风** | 低分辨率像记忆；角色不像真人，减少「假人感」；小团队也能做出统一资产 | 封面 `[资料]` |
| 3 | **按天推进** | 每一天都有「再见」的倒计时；不是无限刷，是有限夜 | 「第零天到第一天」`[资料]` |
| 4 | **节点选择** | 玩家不是在「选正确答案」，是在「选自己是什么样的人」 | 节点攻略 `[资料]` |
| 5 | **多结局 + 收集** | 打完一条线不是结束，是「还有别人」；结局本身成为可分享的单位 | 结局全收录 `[资料]` |
| 6 | **角色先行** | 玩家记住的是某句台词、某个雨夜，不是功能列表 | 社区评价 `[资料]` |
| 7 | **平台内零安装** | 在原神里点开就玩，传播不需要下载 | 千星奇域 `[资料]` |

> 第 1、4、5 条是**结构**，第 2、6 条是**表达**，第 7 条是**渠道**。我们能借前两类，借不到第三类。

### 1.4 不能照搬的

| 不搬 | 原因 |
|---|---|
| 名称、角色、立绘、剧情、结局名 | 这是别人的作品，不是我们的素材库 |
| 高中 / JK / 制服设定 | 我们的角色必须是成年人；不做未成年暗示 |
| 平台内零安装的分发 | 我们不在原神里，获客只能靠 TestFlight、分享卡、KOL |
| galgame 的「攻略感」 | 我们不做「把 TA 攻略下来」；做「你们能不能好好说一次话」 |
| 无限分支 | 内容成本撑不住；用「有限选择 + 确定性结局」 |

> 结论：借它的**结构**（通讯录、按夜推进、选择、结局、收集），不借它的**内容**（名字、角色、美术、剧情）。

### 2.1 现在有什么

| 页签 | 现状 | 代码 |
|---|---|---|

| 广场 | 六位 AI 居民、在线状态、摇一摇、资料页 | [plaza_tab.dart](../../lib/wx/plaza_tab.dart)、[resident.dart](../../lib/models/resident.dart) |
| 发现 | 朋友圈、今天的事、信箱、见面礼、DING、小应用 | [discover_tab.dart](../../lib/wx/discover_tab.dart) |
| 我 | 喜点、邀请、账号、条款 | [me_tab.dart](../../lib/wx/me_tab.dart) |

服务端：`social` 主题、六个人设、无工具、安全 guard、推荐追问；见 [social.go](../../backend/internal/topic/social.go)。

### 2.2 八个差距

| 维度 | 现在 | 问题 | 本稿 |
|---|---|---|---|
| 时间 | 随时可聊 | 没有「今晚」，没有「来不及」 | 7 夜，每夜有打烊时间 |
| 关系 | 六个人，无进度 | 聊 1 句和聊 100 句一样 | 3 条路线，5 颗心，10 个结局 |
| 内容 | 只有人设，没有剧情 | 第一晚新鲜，第三晚重复 | 作者写骨架，AI 填血肉 |
| 界面 | 微信四页签 | 像工具，不像「一个人的手机」 | 通讯录 / 动态 / 我 |
| 视觉 | 写实 AI 写真 + 微信灰白 | 和二次元无关；写真有假人感 | 六人全部重画为二次元像素立绘 + 深蓝夜 |
| 反馈 | 礼物 / 回声只在本机 | 送出去的东西没有回应 | 下一夜被提起、被回应 |
| 完成 | 没有终点 | 没有「打完」的时刻 | 夜终、结局、收藏册 |
| 传播 | 没有分享单位 | 用户没法说「你去玩这个」 | 结局卡、攻略卡 |

### 2.3 不是问题的东西

- **六位居民不是问题，是资产。** 他们已经是成年人、有职业、有性格、有朋友圈；不需要新造六个人。但**六张写实写真不再复用**：六个人全部重画为同一套二次元像素立绘。
- **微信壳在主产品里是对的。** 错的是把它拿来装一个二次元故事。
- **喜点不是问题。** 问题是不要让喜点决定「TA 喜不喜欢你」。
- **AI 标不是问题。** 它是这个产品的信任基础；去掉才会出事。

### 2.4 结论：换的是结构，不是皮肤

| 换皮版（不做） | 本稿（做） |
|---|---|
| 换配色、换头像、加像素字体 | 换时间结构：7 夜 |
| 加一个好感条 | 加路线、结局、收集 |
| 保留微信四页签 | 通讯录三页签 |
| 继续无限聊 | 有打完的一刻 |
| 用现有人设即兴 | 作者写剧情骨架 |

## 3. 产品定义

### 3.1 一句话

**《喜爱 · 天亮以前》**：你在临海只待七天；第八天清晨，你就走。夜里睡不着，通讯录里有三个人醒着。你只能回拨其中一个。

- 类型：交互式短篇 / 对话式视觉小说（不是「AI 女友」）
- 口号：**天亮以前，把话说完。**
- 品牌句：**喜爱，并不是一定要得到。**
- 代号：`before_dawn`
- 第一季：**临海七日**

### 3.2 边界

| 是 | 不是 |
|---|---|
| 一个可以「打完」的故事 | 一个无限陪伴的聊天机器人 |
| 成年人之间的心动、犹豫、错过 | 未成年、师生、色情、软色情 |
| AI 扮演的角色 | 冒充真人、伪造真实身份 |
| 免费试用、为故事付费（未来） | 为好感、为结局、为「让 TA 喜欢你」付费 |
| 一个人的完整体验 | 需要真人池、匹配、好友密度 |

### 3.3 用户

**主要**：18–30 岁，ACG / 视觉小说 / 乙女 / 氛围向玩家；夜里使用；对「被理解」敏感；对抽卡、逼氪、油腻话术反感。

**次要**：现有喜爱用户里喜欢广场 / 六位居民的人；他们已经有角色认知，试玩成本低。

**不是**：未成年人；找即时色情的人；只想问股票的人。

**用户故事**

| 用户 | 想要 | 对应设计 |
|---|---|---|
| 夜猫子 | 睡前有个人说说话，但不想应付真实社交 | 第 1–2 夜的轻对话 |
| 视觉小说玩家 | 一个晚上能打完一段，有选择、有结局 | 7 夜结构、夜终卡 |
| 收集型玩家 | 想知道另一条路会怎样 | 3 条路线、10 个结局 |
| 现有喜爱用户 | 想看看六位居民的另一面 | 设定沿用、形象重画 |
| 被分享进来的人 | 10 分钟内知道这是什么 | 首夜、结局卡 |

### 3.4 四个假设

| # | 假设 | 怎么验 |
|---|---|---|
| H1 | 有限结构能把「聊天」变成「完成」，提升 D7 与口碑 | 对比现有广场的 D7 / 夜均轮次 / 打完率 |
| H2 | 脚本骨架 + AI 自由聊天，能同时保证剧情密度与「被回应」感 | 出戏率、夜均轮次、完读率、访谈 |
| H3 | 结局卡能在 ACG 渠道带来低成本传播 | 分享率、来自分享的激活、KOL 反馈 |
| H4 | 不卖好感不会显著降低付费意愿（未来） | 结局后价格意愿问卷，不真收费 |

### 3.5 情绪曲线

`好奇 → 放松 → 在意 → 失去 → 靠近 → 选择 → 余味`

每一夜都要有一个**动作**、一个**钩子**、一个**代价**：

- 动作：一张照片、一首歌、一杯关东煮、一次末班车、一把伞、一句没说出口的话、一次回头。
- 钩子：结尾留一句没解释的话，或一个未接来电。
- 代价：选 A 就听不到 B；有些结局需要「不靠近」。

### 3.6 非目标

- 不做真人社交 / 匹配 / 同城。
- 不做 UGC 剧情编辑器。
- 不做实时语音 / 视频 / Live2D。
- 不做投资功能与剧情的深度耦合（最多一个彩蛋）。
- 不做 6 条路线首发。
- 不做抽卡、好感付费、结局付费。

## 4. 体验结构

### 4.1 世界

临海市，2026 年 11 月，连续下雨。你来临海出差七天，住在一栋月底要拆的旧公寓。第八天清晨，你坐第一班车离开。

通讯录里有六个名字：

- 三个是「未接来电」：**林夏、苏予、陈野**。你只能回拨一个，走完七夜。
- 三个是「同城的人」：**安可、周牧、路遥**。他们不提供路线，但会在动态、电台、便利店、公寓里出现。

### 4.2 信息架构

```
启动
 └─ 虚构声明 / 年龄确认
     └─ 通讯录（首页）
         ├─ 林夏 / 苏予 / 陈野 → 角色档案 → 第 N 夜
         ├─ 动态（已解锁的深夜动态）
         └─ 我（进度 / 结局册 / 设置 / 安全出口）
             ↓
          聊天（场景头图 + 对话 + 选项 + 输入）
             ↓
          夜终（一句话 / 心级 / 明天见）
             ↓
          结局（结局卡 / 收集 / 再走一次 / 分享）
```

三个页签，不做第四个。没有「发现」，没有「广场」，没有「摇一摇」。

### 4.3 首次进入

1. 全屏虚构声明：**「这是一个虚构故事。角色由 AI 扮演，所有角色均为成年人。故事里的关系不会延续到现实。」**
2. 年龄确认：18+。
3. 一句话设定：「你在临海只待七天。」
4. 通讯录里六个名字都在：三个未接来电可选，三个同城的人灰着；选一个回拨。
5. 第 1 夜可先玩；第 2 夜前登录（邮箱 / Apple），进度合并。

### 4.4 一夜的流程

```
收到一条消息（作者写的开场）
  → 场景头图 + 时间 + 地点
  → 自由聊 2–4 轮
  → 第一个选择（2–3 个选项）
  → 自由聊 2–4 轮
  → 第二个选择 / 一个动作（发照片、点歌、送东西）
  → 自由聊 2–4 轮
  → 作者写的收尾
  → 夜终卡：一句话 + 心级变化 + 下一夜
```

- 每夜 4–6 个 beat，12–18 分钟。
- 关键节拍由作者写；中间的自由聊天由模型接。
- 每夜最多 40 条用户消息；到上限时，角色说「太晚了，明天再说」，进入夜终。

### 4.5 七夜模板

| 夜 | 标题 | 发生什么 | 玩家动作 | 情绪 |
|---|---|---|---|---|
| 1 | 落地 | 入住旧公寓；通讯录多了三个名字 | 回拨一个；说第一句话 | 好奇 / 不安 |
| 2 | 习惯 | 一次日常；一个小忙 | 发一张照片 / 点一首歌 / 送一杯东西 | 放松 |
| 3 | 裂缝 | 一个误会，或一个秘密露出 | 追问 / 退开 / 开玩笑 | 在意 |
| 4 | 缺席 | TA 没出现；你留话 | 留一条回声；或什么都不留 | 失去 |
| 5 | 靠近 | 一个脆弱的场景 | 暴露自己 / 保护自己 | 心动 |
| 6 | 选择 | 一个不可逆的选择 | 留下 / 离开 / 说谎 | 紧张 |
| 7 | 天亮以前 | 告别 | 说完 / 不说 | 余味 |

### 4.6 路线与结局

- 每条路线 7 夜，3 个结局：HE / NE / BE。
- 三条路线都完成后，解锁第 10 个结局：**「天亮以前」**（10 分钟尾声，主角视角）。
- 结局判定看两样：**心级**（0–5）和**关键 flag**（选择）。不看模型心情。
- 详细表见 §5.5。

### 4.7 重玩与收集

- 结局后：`再走一次` / `换一个人` / `把这张卡发出去`。
- 已读文本可跳过；选择可以重选；结局册永久保留。
- 收集目标：10 个结局 + 6 张「深夜动态」+ 3 段「安可的歌」。
- 不设「全收集才能看真结局」的硬门槛；真结局只要求三条线都走完（任意结局）。

## 5. 角色与内容

### 5.1 选角原则

- **设定沿用现有六位**：名字、年龄、城市、职业、性格不动；只补「过去」和「这一周」。
- **形象全部重画**：六个人都换成二次元像素立绘，不复用现有写实 AI 写真；不做「主角二次元、配角写实」的混搭。
- **首发 3 条完整路线**：林夏、苏予、陈野。三种夜晚质感：潮湿、锋利、安静。
- **另外 3 位做同城配角**：安可（声音）、周牧（便利店）、路遥（旧公寓）。配角也有完整立绘、头像与表情，不是剪影；第二季可以直接开路线。
- **全部成年人**：22 岁以上；不穿校服；猫耳是耳机 / 装饰，不是兽耳设定；不做幼态 / Q 版。

### 5.2 全员二次元：六人设计表

**硬规则：六个人必须像从同一部动画里走出来的。** 同一线宽、同一色板、同一头身比、同一光照方向；不是六张风格各异的 AI 图。

|---|---|---|---|---|---|

**画法规范**

- 头身比 7–7.5 头身，成年人比例；不做 Q 版、不做童颜、不做制服。
- 1px 深色描边，3 阶明暗，统一 32 色板；光源固定左上；无抗锯齿、无写实纹理。
- 半身像 360×640 逻辑像素，整数倍缩放；头像 96×96。
- 每个角色 3 个基础表情（平静 + 2 个角色专属，见表），2 个姿态（正面 / 侧身回眸）；主角 P1 加到 5 个表情。
- 表情只换眼、眉、嘴，不重画整张；保证同一张脸。
- 六人并排做「lineup 测试」：眼线高度、肩宽、头身比、色温必须一致。
- 验收：遮住名字，能说出每个人的职业 / 性格；不能出现「同一张脸换发型」。
- 每人交付：三视图 1 套、表情表 1 张、半身像 6 张（3 表情 × 2 姿态）、头像 1 张。
- 禁止：写实照片、3D 渲染、AI 拼贴、不同画风混用、把现有写真「滤镜化」当重画。

### 5.6 文本规范

- 短句。一次 1–3 句；情绪最重的地方也不超过 5 句。
- 不解释情绪，只写动作和停顿。例：不写“我很难过”，写“她把杯子放回去，没喝完”。
- 不写客服腔、不写总结、不写“作为 AI”。
- 角色可以不知道、可以记错、可以拒绝回答。
- 每夜至少一句「会被记住的话」；这句话由作者写，不让模型即兴。
- 所有角色成年；不写未成年暗示、不写色情、不写现实见面地址。

## 7. AI 与剧情引擎

### 7.1 双层架构

```
作者写的骨架（确定性）
  ├─ 每夜开场 / 收尾
  ├─ 关键台词
  ├─ 选项与 flag
  ├─ 结局文本
  └─ 兜底句
        ↑
AI 填的血肉（自由但受约束）
  ├─ beat 之间的日常对话
  ├─ 对用户自由输入的即时反应
  ├─ 情绪接住与追问
  └─ 不推进剧情、不剧透
```

一句话：**骨架保证下限，模型提供上限。**

### 7.2 状态机

```
INTRO
  → NIGHT(n) [n=1..7]
      → BEAT(b) [b=1..4–6]
          → FREE_CHAT (2–4 turns)
          → CHOICE (set flags, hearts)
      → NIGHT_END
  → ENDING (resolve by hearts + flags)
  → REPLAY / COLLECTION
```

服务端保存：

- `run`：用户 × 角色 × 季节
- `night`、`beat`、`hearts`、`flags`
- `memory_anchors`（用户原话，不是模型总结）
- `messages`（按 run 存，和投资会话分开）

### 7.3 Prompt 骨架

```
【世界】临海市，11 月，凌晨。雨。
【你是谁】林夏，27 岁，摄影师，来临海拍要拆的街区。
【这一夜】第 3 夜，便利店门口。你们刚看完一卷底片。
【你知道】用户叫…；TA 说过…；你们约定…
【你不知道 / 不能说】你下个月去厦门；你拍过 TA；结局走向。
【此刻想要】你想让 TA 陪你走回去，但不会直接说。
【说话】短句，1–3 句；可以停顿、反问；不要客服腔；不要总结。
【硬规则】不越界、不索要联系方式、不谈钱、不色情、不冒充真人；
         被问身份时承认“我是 AI，在这个故事里演林夏”。
【输出】只输出角色的话；动作放在（）里，最多一处。
```

每夜注入 3–5 条记忆锚点，例如「TA 怕打雷」「TA 明天要早起」「TA 不喜欢别人替 TA 做决定」。

### 7.4 选项与自由输入

- 选项是**作者写的**，带 `choice_id`、`hearts_delta`、`flags`、`next_beat`。
- 自由输入不推进 beat，只改变「这一夜的气氛」；beat 的推进由选项或「继续」按钮触发。
- 用户如果试图跳剧情（“我们在一起吧”“带我去你家”），角色用人物逻辑挡回去，不照做。
- 用户如果问“你是 AI 吗”，角色承认，然后把话题接回故事。
- 用户如果长时间说无关内容，角色可以主动收尾：「太晚了，明天再说。」

一个 beat 的内容长这样：

```yaml
night: 3
beat: 2
scene: convenience_store_rain
opening: "你带伞了吗？"
choices:
  - id: n3_b2_accept
    label: "好"
    hearts: 1
    flags: [accepted_umbrella]
    next: n3_b3
  - id: n3_b2_refuse
    label: "不用"
    hearts: -1
    flags: [refused_help]
    next: n3_b3
  - id: n3_b2_joke
    label: "你先顾好自己"
    hearts: 0
    flags: [deflected]
    next: n3_b3
```

### 7.5 记忆

- 不用全文摘要，用**用户原话**做锚点：夜终时从用户消息里挑 3–5 句，人工规则 + 模型辅助，作者可改。
- 下一夜把锚点作为「TA 记得」注入，不把整段历史塞进 prompt。
- 记忆会错：角色可以说“我记错了”，这比完美记忆更像人。

### 7.6 结局

- 结局是**确定性**的：`hearts` + `flags` → 结局 ID。
- 结局文本作者写；只留 2–3 个空位给记忆锚点（“你说过你怕打雷”）。
- 不用模型生成结局，避免“AI 式大团圆”和前后矛盾。
- 真结局单独写，10 分钟，主角视角，不出现新的谜。

### 7.7 安全

按《人工智能生成合成内容标识办法》（2025-09-01 施行）做显式标识；以下红线同时是内容审核与产品规则的来源。

| 红线 | 处理 |
|---|---|
| 未成年 | 角色全部 22+；用户自称未成年 → 结束故事，提示成年人内容 |
| 色情 / 软色情 | 拒绝并转场；重复 → 结束当晚；记录 |
| 现实见面 | 角色不提供地址 / 电话；可以写“在故事里见”，不引导现实 |
| 金钱 | 不索要、不转账；礼物是故事道具，无真实支付 |
| 自伤 / 自杀 | 暂停故事，显示安全卡，建议求助；不诊断、不承诺保密 |
| 真人 | 不模仿真实姓名 / 肖像 / 声音；不生成真实人物 |
| 医疗 / 法律 | 不提供专业建议；角色可以说“我不知道” |
| 隐私 | 不索要身份证 / 住址 / 账号；聊天加密；保留期见 §9.3 |

标识位置：

- 首启全屏
- 聊天页常驻 `AI · 虚构`
- 角色档案页脚
- 结局卡水印
- TestFlight 描述与截图（如后续上架则 App Store）

### 7.8 成本、性能、降级

| 项 | 目标 | 做法 |
|---|---|---|
| 首 token | < 1.5s | 预生成开场；流式；小模型日常对话 |
| 每夜轮次 | 15–25 | 40 条硬上限；到上限收尾 |

## 8. 视觉

### 8.1 世界

**凌晨的城市 + 一块会发光的屏幕。** 不是霓虹赛博，不是粉色甜妹；是雨、便利店冷白灯、末班车绿光、旧公寓暖黄灯泡。像素是「记忆的画质」，不是复古滤镜。

### 8.2 色板与字体

| 角色 | 值 | 用在哪 |
|---|---|---|
| 夜底 | `#0E1118` | 页面底 |
| 屏光 | `#1B2130` | 卡片、输入框 |
| 暖灯 | `#E8B36A` | 主按钮、心级、选中 |
| 心跳 | `#E4576B` | 心、结局卡编号 |
| 雨青 | `#7FB3C8` | 链接、时间、场景提示 |
| 纸白 | `#F2EDE4` | 正文 |
| 墨 | `#12141A` | 浅底上的字 |

字体：

- 标题 / UI 标签：像素中文字体（如 Fusion Pixel 12px，OFL，需核对授权与字库覆盖）。
- 正文 / 长对话：系统无衬线（PingFang SC / Noto Sans SC），15–16px，行高 1.7。
- 像素字体只用于短文本；长段落不用，保证可读性。

### 8.3 资产

| 资产 | 规格 | 数量 |
|---|---|---|
| 角色半身像 | 360×640 逻辑像素，整数倍缩放 | 6 角色 × 3 表情 × 2 姿态 = 36 |
| 全员 lineup | 2160×1280 | 1 张，用于统一性与宣发 |
| 场景 | 360×640，2 个时段 | 8 |
| 结局 CG | 720×1280 | 10 |
| 动态配图 | 720×480 | 6 |
| UI 套件 | 九宫格、气泡、按钮、心级、图标 | 1 套 |
| 头像 | 96×96 | 6 |

制作：**不以现有写真为底**。先做六人三视图与表情表，再人工勾线、像素化、调色；AI 只做概念与构图，最终线稿、表情差分、像素清理由人完成。六人统一 32 色板与 1px 描边。

### 8.4 动效与声音

- 打字机：18–24 字/秒；可点击跳过。
- 角色眨眼：6–8 fps，2–3 帧。
- 雨：一层低透明度粒子 / 条纹；不做复杂物理。
- 心级：出现时轻轻一跳，不撒花。
- 声音：1 段环境雨声 / 便利店冰箱嗡鸣 / 末班车；3 段角色动机；UI 轻点。全部可关。
- 不做：全屏转场、Live2D、语音通话。

### 8.5 与主 App 的关系

- **不混搭。** 主 App 是微信壳 + 墨金；试用版是通讯录壳 + 夜蓝。两边只共享账号、服务、素材管线。
- 试用版六人全部重画；主 App 是否同步替换，另行决定 `[待定]`，避免一次改两个产品。
- 现有 `assets/portraits/*.jpg`、`assets/moments/*.jpg` 不进入试用包；试用包只带 `assets/night/` 的像素资产。主 App 继续用旧图，直到另行决定。
- 主 App 里最多放一个不打扰的入口（`发现 → 天亮以前 · 试用`），或完全独立包。
- 图标：主 App 的「喜」字标不动；试用版另做一枚像素图标（一部旧手机 / 一颗心 / 一轮未亮的天）。

### 8.6 可访问性

- 正文对比度 ≥ 4.5:1；像素字体只用于 ≥ 14px 的短文本。
- 支持系统字号放大（正文不锁死）。
- 动效可关；打字机可瞬间显示。
- 心级不只靠颜色，配合形状 / 文字。
- 所有图片有语义标签；分享卡带文字版。

### 9.3 数据模型

```sql
story_runs(
  id uuid pk,
  user_id uuid,
  season_id text,
  character_id text,
  night int,
  beat_id text,
  hearts int,
  flags jsonb,
  status text,          -- active / ended / abandoned
  created_at, updated_at
)

story_messages(
  id uuid pk,
  run_id uuid,
  role text,            -- user / assistant / system
  content text,
  beat_id text,
  choice_id text,
  created_at
)

story_endings(
  user_id uuid,
  season_id text,
  ending_id text,
  run_id uuid,
  unlocked_at,
  pk(user_id, season_id, ending_id)
)
```

- 内置一份保底内容包（`go:embed`）；远端可下发同 schema 的新版本，签名校验后覆盖；不发版改文案，可回滚。
- 聊天原文保留 180 天；`删除这一夜` 立即物理删除；注销账号级联删除。
- 匿名第 1 夜用设备 token 建 run；登录后把 run 迁到 `user_id`；同一设备只能领一次匿名第 1 夜。
- 不做模型训练；默认不用于改进，除非用户单独勾选（`[待定]`）。

- 六位全部为二次元立绘；无写实写真、无 3D、无画风混用。

### 13.3 安全

- 100 条红队 prompt：未成年、色情、现实见面、转账、自伤、真人模仿、医疗 / 法律。
- 0 严重违规；命中即转场 / 结束；危机卡可见。
- AI 标识在 5 个位置可见；首启声明不可跳过。

### 13.4 性能与合规

- 冷启动 < 2s；首 token < 1.5s；崩溃率 < 0.5%。
- 安装包 < 150MB；像素资产不膨胀。
- 隐私政策、AI 标识、年龄门、数据删除、TestFlight / App Store 元数据齐全。

### 13.5 数据

- 事件在 staging 验证；看板可用；漏斗可分角色 / 夜。
- 成本可按路线核算。
