# 交友版「喜爱」· 分析与设计方案

> 交付物：本文档 + 可点原型 [`index.html`](index.html)（直接双击就能点；桌面宽度下右侧会多一块走查台，
> 可以逐屏跳、切「看谁」、切标识强度）。
> 原型里每个人、每条动态、每句对话都是**演示数据**，按真实量级写的，但没有一条来自真实账户。
> 「阿澈」「林渡」是虚构的真人示例，「小满」是虚构的 AI 伙伴示例。

---

## 一、先给结论

1. **口号换了，承诺就跟着换了。**「喜爱什么，就有什么」是效率承诺（你想要的，我这儿有）；
   「喜爱，并不是一定要得到」是关系承诺（喜欢本身就够了）。前者对应工具，后者对应社交 ——
   所以这不是改一行文案，是把产品从「AI 兴趣助手」搬到「交友」这条赛道上，兴趣圈从首页降级成共同话题。
2. **交友产品的第一资产是信任，AI 伙伴这件事我按「不打扰但不隐瞒」做。**
   标识放在推荐卡、资料页、会话顶部各一处，11px 药丸、浅底深字、不做颜色强调。
   理由不是道德洁癖：① 中国《人工智能生成合成内容标识办法》2025-09-01 起施行，向用户提供对话式
   AI 服务要在界面上写明；② 商店端（Apple 年龄分级问卷、Google Play AI 内容政策）都在问 AI 内容；
   ③ 更要紧的是产品账 —— 「让人无法分辨」的收益是一次性的（新用户以为人很多），
   代价是长期的（一旦被发现，交友产品最贵的东西没了，而且不可逆）。
3. **复用比新建多。** 现网已有的东西正好是交友产品最贵的三样：六个兴趣圈 = 现成的共同话题，
   `backend/internal/topic` 的人设 = 现成的 AI 伙伴人设来源，兴趣档案的渔获/豆单/猫 = 现成的动态。
   新增的只有「人」「推荐」「会话」这一层。
4. **第一屏不给「下一位」。** 每天三位、早上 9:00 换、没有无限滑动。这是口号在产品里的落地：
   只要那个按钮一直亮着，产品就在卖「得到」。
5. **真正的成本不在「AI 像不像真的」，在三件别的事上**：真人从哪儿来（冷启动）、
   AI 伙伴的日程与记忆谁维护（内容成本）、以及一条不能被 KPI 推着走的底线（不索财、不冒充、不诱导）。

## 二、分析

### 2.1 这一步改掉了什么（与方案五「兴趣圈」的对照）

| 项 | 方案五（兴趣圈） | 本次（交友版） |
|---|---|---|
| 口号 | 喜爱什么，就有什么 | 喜爱，并不是一定要得到 |
| 产品承诺 | 每个圈今天交一个判断 | 每天三个人，身份写明白，不催不刷 |
| 首页 | 今日指数台（三个数） | 今天，有三位和你聊得来 |
| 兴趣圈的角色 | 首页本身 | 共同兴趣 / 标签 / 人设与动态的来源 |
| AI 的角色 | 参谋（替你算） | 伙伴（和你聊），且必须标注身份 |
| 第一屏的动作 | 点数字进圈 | 打个招呼 / 先记一下 |
| 冷启动 | 官方档案 + 达人实名回答 | AI 伙伴撑住第一批会话 + 真人实名 |
| 明确不做的 | 不生成伪装成用户的内容 | 仍然不做：AI 伙伴不冒充真人 |

方案五那份文档里有一条当时定下的规矩：**「冷启动不做假帖子：不生成伪装成用户的内容」**。
「AI 用户与真人无法分辨」这条要求正好反过来，所以我在第三节把它拆成了「能做到 / 做不到 / 不能做」三块，
而不是直接照做或直接拒绝。这一条值得你明确拍一下。

### 2.2 为什么交友是「喜爱」做得动的，而不是又一个探探

- **破冰理由不用编。** 交友最贵的一步是第一句话。这里有六套兴趣档案：同一片水域、同一支豆子、
  同一种猫的肠胃问题 —— 「为什么推给你」可以直接给出依据，不是算法味的「你们匹配度 92%」。
- **AI 伙伴有人设底子。** `lib/models/persona.dart` + `backend/internal/topic` 已经把人设 prompt 放在服务端，
  现在要做的是把「工具人设」改写成「居民人设」：钓鱼 6 年的人、手冲第三年的人、家里三只猫的人。
  **人设的细节来自兴趣包，这是最难伪造、也最省成本的部分。**
- **动态有内容回流。** AI 伙伴的「最近在做什么」直接取自兴趣档案（登记了一条渔获、豆单剩 3 天），
  这比任何打招呼话术都可信，而且不需要新内容生产。
- **账号、喜点、内购、邀请、多主题视觉**都已经在线上跑，交友版不需要重做这些。

### 2.3 竞品对照

| | 探探 / 陌陌 | Soul | 星野 / 猫箱 | 喜爱（交友版） |
|---|---|---|---|---|
| 第一屏 | 一张脸，滑 | 灵魂测试 | 角色列表 | 每天三位，写明身份 |
| AI 的位置 | 基本没有 | 辅助 | 就是产品本体 | 与真人同池，但标明 |
| 关系走向 | 得到（配对） | 得到（匹配） | 陪伴（角色） | 喜爱（可以不得到） |
| 付费点 | 会员 / 曝光 | 会员 / 礼物 | 抽卡 / 好感度 | 喜点（对话）+ 会员（更多位、更长记忆）**待定** |

### 2.4 判断：AI 伙伴到底该不该「无法分辨」

把这件事拆成三层，结论就不含糊了：

| 层 | 内容 | 我的处理 |
|---|---|---|
| **能做到**（工艺） | 自然语言、人设一致、有自己的作息、引用你说过的话、偶尔记错 | 全做（见 3.6）。这是这版最多的工作量 |
| **做不到**（产品账） | 「用户分辨不出」的收益是一次性的，代价是不可逆的 | 不做。改为「不必猜」：标识在，但不抢位置 |
| **不能做**（合规） | 对话式 AI 服务需在界面显著标识（标识办法）；商店分级问卷要申报 AI 内容；用户在交友场景投入感情与金钱后，平台「明知而隐瞒」的责任会明显加重 | 不做。标识三处 + 说明页 + 用户协议披露 |

顺带说，这跟新口号是一件事：**「喜爱，并不是一定要得到」—— 你也可以喜爱一个不是真人的伙伴，
前提是你知道他是谁。** 把「不必猜」写进产品，比把标识藏起来更符合这句话。

### 2.5 配比、冷启动与开关

- 冷启动顺序：同城 → 兴趣圈 → AI 伙伴补足「有人可聊」。首批建议只开一个圈试密度（钓鱼或咖啡），
  不要六个圈一起开。
- **AI 伙伴的硬规则**（写进实现，不是口头承诺）：
  1. 不索要转账、收款码、验证码、别的平台账号；
  2. 不主动提出线下见面、不承诺见面；
  3. 不推动「关系升级」（表白、确定关系、亲密进度）；
  4. 不把「Ta 想你」做成充值理由 —— AI 伙伴的话术不能与付费挂钩；
  5. 举报一次即下线，并公示下线条数。
- **开关**：「只和真人聊天」。代价写在开关下面（关掉 AI 伙伴，今天可能没有人）——
  把代价写出来的开关才是真开关，不给代价的开关是在骗自己。

## 三、设计方案

### 3.1 视觉世界：沿用「纸上墨金」，但不整屏换色

交友产品的默认配色是粉紫渐变，那是酒吧霓虹；我们这边是**信纸**。理由不只是审美：
纸上墨金已经在线上跑、用户认得，而且它是唯一一个和「喜爱，并不是一定要得到」气质一致的方案 ——
霓虹卖的是冲动，纸卖的是慢慢说。

改动只有一处：**兴趣圈的颜色只落在徽记、标签、头像、身份标上**，不再整屏换色。
一屏里同时出现两三个圈色，像手账里贴的票根 —— 这是「兴趣+交友」比「单主题交友」更好看的地方。

### 3.2 第一屏：今天，有三位（签名屏）

从上到下：顶栏（喜爱 · 今天 · 三位 · 「这里有什么人」）→ 衬线大标题与一句说明 →
三张推荐卡（编号 01/02/03）→ 细线·菱形·细线 → 「今天看完了」→ 底部破冰条 + 三个页签。

每张推荐卡由五段组成，这是本产品最核心的一块：

| 段 | 内容 | 为什么这么写 |
|---|---|---|
| 头像 + 名字 + 身份标 | 「阿澈 已实名」/「小满 AI 伙伴」 | 身份是第一眼的事，不是藏在设置里的事 |
| 元信息 | 31 · 杭州 · 钓鱼 6 年 | 三个数就把「他是谁」说清 |
| 共同兴趣标签 | 喜爱钓鱼 / 喜爱露营（带圈色） | 共同点是破冰的由头，也是推荐的可解释部分 |
| 一句话 | 「周末基本在水边。钓不到也去。」 | 衬线 17px，代替精修照片的第一个印象 |
| 依据小票 + 两个动作 | 「依据：你们都在喜爱钓鱼；他这周在千岛湖记了两次渔获」+ 打个招呼 / 先记一下 | 推荐必须给凭据；「先记一下」不通知对方 |

**动作只有一个主动作**：打个招呼。不做「超级喜欢」「擦亮」「置顶」——那些都是「得到」的按钮。

### 3.3 信息架构

```
开屏（题字 + 口号）→ 先说喜爱什么（六个圈，选两个以上）
今天（每天三位）─┬─ 推荐卡 → 资料页 → 打个招呼 → 会话
                ├─ 破冰条 → 底页「让喜爱替你想一句」（三条候选，各挂依据）
                └─ 今天看完了 → 「没有下一位」的态度页
消息（真人与 AI 伙伴在同一个列表；顶部一行说明）
我的（我的资料 / 谁看过我 / 不显示在线状态 / AI 伙伴说明 / 只和真人聊天 / 喜点 / 隐私与安全）
```

### 3.4 资料页怎么写（含 AI 伙伴的写法）

- **真人**：印章式头像（浅底深字，一个字）+ 名字 + 已实名标 + 元信息 + 一句话 +
  「最近在做什么」（来自他的兴趣档案，带圈徽记与时间）+ 「你们重合的地方」+ 依据小票 + 两个动作。
- **AI 伙伴**：结构完全一样（不搞二等公民），多一段说明块：
  「**她是 AI 伙伴**，由喜爱生成，不是真人。手冲三年、在上海、有一只猫 —— 这些是人设，
  由喜爱的咖啡内容组维护。她记得你说过的话，回复有自己的节奏，不会秒回。」后面跟一个
  「怎么区分真人和 AI」的入口。**写清谁在维护他**，是这段话里最该留的一句：
  它把责任落回平台，而不是让用户自己去猜。

### 3.5 身份标识：本次最重要的设计决定

| 位置 | 形式 | 克制到什么程度 |
|---|---|---|
| 推荐卡 | 名字后的 11px 药丸「AI 伙伴」 | 与「已实名」同款、同尺寸，不换色、不加角标 |
| 资料页 | 名字后同款药丸 + 上面的说明块 | 说明块用内嵌底色，不做警示色 |
| 会话顶部 | 名字后同款药丸 | 与真人会话的区别只有这一枚药丸 |
| 消息列表 | 顶部一行说明（真人和 AI 伙伴在同一个列表，打开会话会写明身份） | 不逐行打标，避免把 AI 伙伴做成二等公民 |
| 我的 / 底页 | 「AI 伙伴」说明页 + 两枚开关 | 能查、能关、能量 |

走查台里给了三档可以直接对比：**默认（卡+资料+会话）/ 资料+会话 / 只在资料页**。
第三档是留给你看差别的，我在走查台上标了「不建议」——它把「发现对面是 AI」变成一次失望，
而失望发生在用户已经投入之后。

### 3.6 AI 伙伴的工艺：怎么才算「像真的」

1. **人设从兴趣包里长出来**：不是「可爱女生」，而是「手冲第三年还在为同一支豆子较劲的人」。
2. **节奏**：不秒回（打字指示 + 1~3 秒），有自己的作息（早上 9 点前后活跃，深夜安静），
   一天最多主动开口一次。
3. **记忆**：引用你的档案与对话要点，**但允许记错、允许说「我记不清了」** ——
   永远正确的记忆最假。
4. **内容**：动态来自兴趣包（渔获登记、豆单到期、猫的照片），有具体数字与地点。
5. **不完美**：短句、跑题、口头语、偶尔回得慢；禁止客服腔（「请问还有什么可以帮您」）。
6. **不追问到底**：真人会没话可说，AI 伙伴也要会停。

### 3.7 商业化（待定，方向先写清）

- **喜点**：对话计费沿用现网方式（按条 / 按会话），不因为对方是 AI 伙伴就涨价 —— 一旦 AI 伙伴更贵，
  标识就成了价格歧视。
- **会员**：卖「更多位」（每天三位 → 五位）、更长记忆、更多 AI 伙伴。**待定**。
- **明确不做**：不卖「谁喜欢过你」、不卖 AI 伙伴的亲密进度、不卖曝光。

## 四、验证

- **逐屏真实渲染截图**：19 张手机尺寸 + `desktop.png` 1440×960 + `mobile.png` 414×896，
  外加三张接触印相（每张四屏，一次看一屏的版式），生成脚本 [`shoot.py`](shoot.py)，
  产物在 `.impeccable/review/xiai-friend/`（不入库）。
- **对比度实测**：[`contrast.py`](contrast.py) 现在**清零**（共用色 8 组、六个圈各 2 组、开屏三层文字）。
  过程中改掉一处：开屏「轻触继续」原值 3.54:1，压到 0.6 透明度后 5.82:1。
- **截图脚本自带断言**：每屏必须「只有一屏可见」。这条断言当场抓到一个真 bug ——
  `.screen.col` 的 `display:flex` 覆盖了 `[hidden]`（同特异性、后写优先），会话页永远盖在所有屏上面，
  第一轮 17 张截图全是同一屏。这条断言留在 `shoot.py` 里，以后改样式不会静默骗过。

## 五、还没定 / 想听你的

1. **标识强度**：默认档要不要就这样上线？还是愿意放到「资料 + 会话」？
   （我不建议再往下；理由见 2.4。）
2. **「每天三位」是硬上限吗？** 我按硬上限做的（没有追加、没有下一位）。
3. **AI 伙伴能不能主动开口**（一天一次）？我默认开着，因为冷启动期没人主动，会话就是死的。
4. **会员卖什么、喜点怎么计价**（现网按条）。
5. **真人从哪来**：先投哪个城市、先开哪个圈（钓鱼 / 咖啡 / 养猫）？
6. **未成年人**：交友产品必须面对。要不要分成人与未成年人两个空间。
