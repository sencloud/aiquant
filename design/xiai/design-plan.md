# 方案五「兴趣圈 AI 助手」· 分析与设计方案

> 交付物：本文档 + 可点原型 [`index.html`](index.html)。
> 直接双击 `index.html` 就能在浏览器里点；桌面宽度下右侧会多一块走查台（列屏、切圈换色、看状态）。
> 原型里的所有数字、渔获、豆单、体重、装备清单都是**演示数据**，按真实量级取值，但没有一条来自真实账户。

---

## 一、先给结论

这个方向的机理是对的，但它现在的写法有一半是把 AI 产品做成了内容产品。三句话：

1. **「喜爱」是这一个方案里最值钱的资产，不是名字好听**：现网 App 已经是多主题架构
   （`lib/topics/`，每个主题只换五个颜色值），「兴趣圈」是把它从「切主题」升级成「切圈」——
   框架、换色、账号、喜点、内购全部复用。这一条把方案从「重做一遍」降级成「加一层 + 做深一个圈」。
2. **首页必须是「判断」，不能是「信息流」**：原方案的首页是「圈子卡片 + 今日推荐 + 问问 AI」，
   这是每个习惯类 App 的默认形状 —— 用户看完不知道该干嘛，AI 也只是一个按钮。
   改成「今天，先看这三个数」：每个圈只交一个判断，点数字进圈。
3. **动态圈是排期最靠后的一条，不是第二条**：社区冷启动与小红书正面对撞，且与「AI 先答、
   达人升维」的产品逻辑相反（社区逻辑是内容自增长）。建议先做成「渔获登记处 + 经验问答」，
   它靠档案和 AI 就能转起来，不依赖发帖量。

## 二、分析

### 2.1 为什么这个方向成立（机理）

兴趣是少数几个「用户自己会回来」的场景：他不会每天打开一个效率工具，但会每天看自己的鱼情、
豆子还剩几天、猫粮够不够。而每个兴趣里都有一层稳定的信息差与决策焦虑：

| 兴趣 | 决策焦虑 | AI 能接住的那一半 |
|---|---|---|
| 钓鱼 | 买什么竿、去哪、几点去、什么天气出鱼 | 预算 → 配置方案；天气 + 历史记录 → 出钓时段 |
| 咖啡 | 豆子怎么挑、参数怎么调、该不该买磨豆机 | 口味偏好 → 豆子匹配；烘焙日 → 冲煮参数 |
| 养猫 | 猫粮怎么选、症状严不严重、行为什么意思 | 记录 + 公开兽医资料 → 排查顺序与就医线 |
| 健身 | 今天练还是歇、动作怎么改、要不要买装备 | 恢复分 → 今日计划；训练记录 → 该不该买 |

这三件事 AI 恰好比搜索引擎强：**筛选、个性化、以及把结论说在前面**。

### 2.2 我们其实已经有一半了

按仓库现状（`PRODUCT.md` / `lib/topics/`）逐条对齐：

| 方案五需要的能力 | 现状 | 差的 |
|---|---|---|
| 多兴趣并存 | 已有：多主题包 + 服务端按 `topic` 区分人设与工具白名单 | 多圈首页（现在首页是单主题的对话页） |
| 每个圈一套视觉 | 已有：`TopicPalette` 只换五个值（品牌 / 主色深 / 浅底 / 纸 / 弱字） | 新增三个圈的取值 |
| 圈内 AI 工作流 | 已有：对话 + 图片多模态 + 钓鱼的出钓指数、钓点地图 | 把「能做的事」产品化成入口 |
| 我的档案 | 部分：钓鱼有渔获记录；钱有证伪档案 | 档案 → 推荐的回流闭环 |
| 计费 | 已有：喜点、邀请、iOS 内购 | 会员 SKU |
| 兴趣测试 / 选圈 | 已有：首启选主题页（同一个组件可直接复用） | 从「选主题」改成「答 3 题推荐圈」 |

结论：**这不是一个从零开始的产品，而是一次信息架构升级 + 一个标杆圈的做深。**

### 2.3 逐条审视原方案（哪里对、哪里要改）

| 原方案 | 判断 | 我的处理 |
|---|---|---|
| 首页：我的兴趣圈卡片 + 今日推荐 + 问问 AI | 结构太通用，AI 退化成按钮 | 改成「今日指数台」：首页只给判断，且允许判断是零 |
| Tab1 AI 参谋（装备/出钓/识鱼/钓点/教程） | 对，但「五件事平铺」等于没重点 | 每圈先给一张**今日结论卡**，再列「AI 能替你做的事」；点任意一条直接带着问题进对话 |
| Tab2 动态圈（社区） | 风险最大：冷启动无内容、与小红书硬碰 | 改成「渔获登记处 + 经验问答」：发帖是登记事实，AI 先答、达人实名补充，按时间倒序不做算法 |
| Tab3 我的档案 | 对，而且被低估了 | 提升为推荐引擎的输入端：档案 → 「该升级什么了」 |
| Tab4 商城 / 好物 | 「商城」会立刻变成货架 | 改成「该升级什么了」：不做货架，做「依据你的档案，你该换线组了」；每件商品挂小票；也允许写「暂时不用买」 |
| 每圈专属知识库与工作流 | 对，但「专属」要能被验证 | 落成三件可验证的事：专属工作流（出配置方案）、专属口径（闸门/指数怎么算）、档案记忆（小票可追溯） |
| 商业模式：佣金 / 会员 / 达人咨询 / 品牌 / 数据服务 | 前三条成立，后两条要分开看 | 会员 = 深度分析 + 不限量档案；达人咨询放在 AI 兜底之后（AI 答不了才转人工）；**数据服务建议放弃**（与「跨圈记忆默认关」的隐私承诺正面冲突，且用户能感知） |
| 风险：兴趣太散 / AI 幻觉 / 冷启动 / 选不出兴趣 | 缺两条 | 补：① AI 的兜底不是「更自信」，是**把不确定写出来**；② 兴趣扩张的准入线是「这个圈今天能不能被一个数说清楚」 |

### 2.4 和竞品的差异（修正版）

原方案的对比表方向对，但把差异说成了「功能更多」。真正的差异只有一条：**第一屏给判断，不给内容。**

| 竞品 | 它的第一屏 | 我们的第一屏 | 差距在哪 |
|---|---|---|---|
| 小红书 | 内容流（看别人） | 今天该做什么（看你） | 它解决「逛」，我们解决「决定」 |
| 什么值得买 | 商品与价格 | 你的档案缺什么 | 它按品类，我们按你 |
| 垂直社区（钓鱼人） | 帖子列表 | 今天的鱼情与你的时段胜率 | 我们有时序数据与个人档案 |
| ChatGPT | 空白输入框 | 已经替你算好的三个数 | 我们有档案、圈子口径与可追溯小票 |

### 2.5 需要你拍板的商业与排期判断

- **冷启动不做假帖子**：不生成伪装成用户的内容。冷启动 = 官方档案（可核对的公开数据）+ 达人实名回答 +
  AI 兜底。这样即使没人发帖，产品也是完整的。
- **佣金必须与推荐解耦且可见**：每件商品挂小票（依据来自你的档案与实测数据）。这条不是道德洁癖，
  是「越用越懂你」这个壁垒的护城河 —— 一旦排序可以被钱影响，档案就没人信了。
- **会员定价 ¥18/月**（原型里的演示值）：卖的是跨圈深度分析、每月装备盘点、档案不限量；
  对话仍按喜点计费（这是现网已跑通的计价方式，不要动）。
- **一个圈的准入线**：能被三个数说清楚才开圈。这也是为什么原型里健身圈的商城写着「暂时不用买」——
  留白本身是结论，也是产品态度。

## 三、设计方案

### 3.1 视觉世界：继承，不重做

理由不是保守，是**收益结构**：纸上墨金（纸底 `#F3F0E8` / 墨 `#1F1C17` / 墨金 `#9E6322`）已经上线，
用户认得；而兴趣圈需要的「一屏一色」能力，现网的主题包机制已经在跑。所以：

- **首页属于品牌本身**（墨金）：它是「喜爱」的首页，不属于任何单个兴趣。
- **进圈即整屏换色**：纸底、主色、选中态一起换 —— 把原来的「切主题」变成「切圈」。
  一个圈只换五个值，白面、墨、发丝线、语义色（涨跌/警示/信息）全圈共用。

### 3.2 第一屏（本轮锁定的结构：今日指数台）

结构来自结构选型（骰子发三张，选的这张）。它同时吸收了三张被淘汰方案里可复用的规则：

| 来源 | 吸收的东西 | 落在哪 |
|---|---|---|
| 鼓机步进排 | 一条不断行的时间轨 + 「现在」的追光 | 每行的时辰轨（钓鱼按小时、咖啡/养猫按天） |
| 字符渲染 | 密度即信息 | 所有数字同列等宽、按同一列对齐 |
| 影子集市 | 每件货挂一张小票 | 每条结论/推荐下方的小票行 |

第一屏从上到下：顶栏（喜爱 · 5 个圈 · 3 个今天有话说）→ 衬线大标题「今天，先看这三个数」
→ 三行判断（圈徽记 + 等级 → 大数 + 判定 → 八格时辰轨 → 一句结论 → 来源小票）
→ 常驻「问问 AI」输入条 → 首页 / 圈子 / 我的。

**签名交互是时辰轨**：它把「今天什么时候该去」压成一条不断行的轨道，现在的位置是一根细线 +
刻度行（`06:00 · 现在 15:20 · 22:00`），最好的时段是轨道上最深的两格。换圈时它换色、换尺度。

### 3.3 信息架构

三个一级页签 + 圈内四段 + 两个二级页：

```
首页（今日指数台）──┬─ 点数字 → 圈内 ─┬─ AI 参谋（默认）→ 对话
                    │                  ├─ 动态圈
                    │                  ├─ 我的档案
                    │                  └─ 好物
                    ├─ ＋ → 兴趣测试（3 题 → 推荐 2 个圈）
圈子（目录：全部圈 + 添加 + 今日一行）
我的（喜点 / 会员 / 跨圈数据 / AI 与隐私 / 邀请）
```

与原方案的对应关系：原「圈内四个 Tab」保留，但顺序与职责改写 ——
**AI 参谋**变成「今日结论 + 能做的事」，**动态圈**变成「登记处 + 问答」，
**我的档案**变成推荐引擎的输入端，**商城**改名「好物」，内容是「该升级什么了」。

### 3.4 圈内四页怎么写

- **AI 参谋**：与首页同一枚签名（今日结论卡 + 时辰轨 + 小票），尺度一致；下面列「AI 能替你做的事」，
  每条点下去带着问题直接进对话（不要求用户自己想怎么问）。
- **动态圈**：帖子 = 事实行（鱼种/重量/水域/风/时间）+ 正文 + AI 标注 + 追问胶囊，
  达人实名补充排在 AI 之后；问达人的帖子由 AI 先给一版，答不了才出现「转人工付费咨询」。
- **我的档案**：战绩 / 装备库 / 等级 / 消费统计。装备库里可以标出「三年未换」，这一条直接回流到好物。
- **好物**：标题是「该升级什么了」，每件商品带一张小票（凭什么推给你）+ 三平台比价 + 评测摘要
  （含负面：如「二八调腰力偏硬，钓小鱼偏钝」）。没有缺口就写留白。

### 3.5 对话的结构：结论先行 → 方案卡 → 依据小票

一段完整对话由五段组成，这是本产品真正的「AI 差异化」：
衬线结论句（先给判断）→ 两句话理由（说清为什么）→ 方案表（品类 / 型号 / 为什么 / 价格）
→ 预算分配条（同一品牌色分层，不是彩虹图）→ 依据小票（你的记录 → 公开数据 → 模型假设）
→ 追问胶囊。用户追问「凭什么」时，回答把三层依据分开列出，并写清哪一层最软。

### 3.6 五个圈各自交什么

| 圈 | 主色 | 纸 | 今天交的数 | 圈内专有工作流 |
|---|---|---|---|---|
| 喜爱钱 | `#9E6322` 墨金 | `#F3F0E8` | 「—」今天没有要说的（允许结论是零） | 证伪闸门：样本 → 成本尺度 → 分年 → 回撤 |
| 喜爱钓鱼 | `#1F6A7A` 湖青 | `#EEF2F0` | 出钓指数 72 · 适合出钓（15:00–18:00） | 预算配置方案、时段概率、钓点与禁渔 |
| 喜爱咖啡 | `#6F4A2A` 深焙褐 | `#F2EFE9` | 赏味期还剩 3 天 | 风味匹配、冲煮参数、豆单到期提醒 |
| 喜爱养猫 | `#6E5A8C` 绒紫 | `#EFEBF2` | 猫粮剩 6 天 · 该补猫砂 | 症状排查顺序与就医线、猫粮成分、行为解读 |
| 喜爱健身 | `#45536B` 铁蓝灰 | `#EDEFF2` | 今日恢复 58 · 建议轻量 | 恢复分 → 今日计划、动作纠正、补剂缺口 |

五个主色对白字都过 4.5:1（实测 4.93 / 6.17 / 7.81 / 5.99 / 7.77）。主色一律不取绿（涨跌沿用国内惯例，
绿 = 跌）。其中**墨金的弱字原值 `#7C746A` 压在纸面只有 4.04:1**（`DESIGN.md` 里记的是 4.9），
建议压深一档到 `#726B61`（4.62:1）；其余四个圈的弱字原值即达标。

### 3.7 建议新增到 `DESIGN.md` 的构件

| 构件 | 语义 |
|---|---|
| `WkIndex` | 今日判断行：圈徽记 + 等级 / 大数 + 判定 / 时辰轨 / 一句结论 / 小票行 |
| `WkRail` | 时辰轨：八格时间条，`现在` 一根细线，最佳时段最深；换圈换尺度 |
| `WkTicket` | 来源小票：把结论拆成「你的记录 / 公开数据 / 模型假设」三层 |
| `WkEmpty` 的新用法 | **结论为空**是一种合法结论（钱圈：今天没有要说的） |

### 3.8 状态与边界（原型里已实现）

新用户没有圈（空状态 → 兴趣测试）／AI 回答中（正在按你的档案算）／小票底页／会员底页／
兴趣测试三步 + 推荐结果／账号未登录（我的页）／拍照识鱼已下线（按钮标注不可用）／
没有装备缺口时好物页写「暂时不用买」／样本不足时钱圈写「样本不足，不算淘汰」。

### 3.9 无障碍与实现约束

- 正文 15px、次级文字压到 4.5:1 以上（含上面那处修正）；等宽数字避免多格并排跳动。
- 系统「减少动态效果」打开时，轨道与进度条不再入场。
- 键盘焦点可见（`focus-visible` 用品牌色描边）；输入框有 `caret-color`。
- 零外部请求：不下载字体、不加载图片，全部由系统字体 + CSS 画出来 —— 这也是这款 App 现有做法
  （不打包 CJK 字体，省几十 MB 包体）。

## 五、还没定 / 想听你的

1. 圈内四页要不要现在就做进真实 App？如果要，建议先做钓鱼圈（`lib/topics/fishing`）的

   建议第一批只要求「三件必填」（预算、常去地点、最近一次记录），其余由 AI 从对话里自动沉淀。

### 6.2 三个新构件（加进 `DESIGN.md` 的 Components 表）

| 构件 | 语义 | 用法 |

| `WkIndex` | 今日判断行 | 首页与圈内共用「今天」卡：圈徽记 + 等级 / 大数 + 判定 / 时辰轨 / 一句结论 / 小票行 |

### 6.3 `WkEmpty` 增加一种用法

**「结论为空」是合法结论**（钱圈今天写「— 今天没有要说的」）。空状态必须说清两件事：
为什么现在没有、什么时候会有。这条要写进 `DESIGN.md` 的空状态说明，否则实现时容易被填成假数据。
