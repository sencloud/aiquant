# 喜爱 × Airi：把「AI 伴侣」做活

> 调研对象：<https://lastndays.com/repo/moeru-ai/airi>（moeru-ai/airi，MIT）。
> 本文只给方案，不改代码。范围为 1.9.0 之后的「单伴侣」版本。

## 一、Airi 做对了什么

Airi 不是一个聊天框，它把虚拟角色拆成五个持续运转的部分：

| 层 | Airi 的实现 | 它解决的事 |
|---|---|---|
| **Brain** | LLM + 工具 + 插件（Minecraft / Factorio / Discord / Telegram） | 她有自己的生活与能力，不只是回答问题 |
| **Ears** | 浏览器/Discord 音频输入、端侧语音识别、说话检测 | 你可以直接说，不用打字；她知道你什么时候说完 |
| **Mouth** | 多供应商 TTS（含阿里云）、流式播放 | 她用声音回应，有语气、有停顿 |
| **Body** | Live2D / VRM，自动眨眼、看向你、待机小动作 | 她「在场」，不是一张会发消息的图 |
| **Memory** | 浏览器内数据库（DuckDB WASM / pglite）、Memory Alaya（进行中） | 她记得你们之间发生过什么 |

另外两点是产品层的：

- **角色是可替换的容器**：形象、声音、人格分开，换皮不换关系。
- **多端同一个人**：Web / 桌面（Tamagotchi）/ 手机（Pocket），同一份灵魂。

## 二、值得借鉴的 6 件事（按性价比排序）

1. **待机生命感**：自动眨眼、呼吸、视线跟随。Airi 的 Body 层里最便宜、最见效的一刀。
2. **实时语音**：Ears + Mouth 形成「说—听—说」；语音比文字更像陪伴。
3. **连续性记忆**：不是把整段聊天塞回 prompt，而是抽取「事实 / 偏好 / 约定 / 情绪片段」，下次自然提起。
4. **主动性**：她会按时间、你的作息、你们上次聊到的事先开口（我们已经有一版模板，下一步交给服务端排程）。
5. **情绪表达**：回复带情绪标签 → 表情、语气、动作一起变（不只是文字变了）。
6. **形象即皮肤**：我们已经做了「遇见」；把它升级成「形象 + 声音 + 说话习惯」的一整套，而不是只换脸。

## 三、不照搬的部分

| Airi | 我们不做 / 晚做 | 原因 |
|---|---|---|
| Live2D / VRM 全量建模 | 先做**分层 2D 立绘**，Live2D 作为二期评估 | Flutter 端 Live2D 插件不成熟，首版先保证稳、包体小、iOS 表现一致 |
| Minecraft / Factorio 陪玩 | 不做 | 与「陪伴」核心无关，成本极高 |
| 自托管模型 / 本地推理 | 不做 | 我们是手机 App，推理在服务端；保持低功耗 |
| 角色卡 UGC 市场 | 二期之后 | 先证明单角色留存，再谈生态 |
| 无限主动消息 | 不做 | 频率上限、夜间静默、可一键关；陪伴不能变成骚扰 |

## 四、喜爱的目标形态（体验剧本）

**晚上 9 点，你打开 App。**

1. 门开——她已经在房间里（当前 1.9.0 的「你来啦」升级为可交互场景）。
2. 她抬头看你，眨了下眼：「回来啦。今天收盘那会儿，你是不是有点烦？」
3. 你按住说话：「还行，就是没拿住。」她边听边点头，等你说完才开口。
4. 她说的时候嘴型跟着声音动，语气放慢；说到「没拿住」时看了你一眼。
5. 你打字或走开，她会回到待机：翻书、看窗外、偶尔眨眼。
6. 第二天早上，她发来一条：「昨天你说的那只票，今天开盘前要不要一起看一眼？」

这六步对应：**Body → Memory → Ears → Mouth → Emotion → Proactive**。

## 五、技术映射（Flutter + 现有 Go 后端）

### 5.1 Body：分层 2D「活立绘」

- 资产拆层（每套形象）：`base`（身体/衣服）、`hair-back`、`hair-front`、`eyes-open`、`eyes-closed`、`mouth-{a,i,u,e,o}`、`brow`。
- Flutter `AnimationController` 驱动：呼吸（整体 1–2px 位移 + 1.5% 缩放，4s 循环）、眨眼（随机 3–6s，80ms 闭眼）、视线跟随（按触摸点做 2–4px 位移）、说话嘴型（TTS 音量包络或 120ms 帧循环）。
- 情绪状态机：`calm / happy / shy / thinking / listening / sad`，驱动眉眼与轻微位移；由服务端回复里的 `emotion` 字段触发。
- 资产来源：继续用百炼生成**同一角色的多表情/多角度**，用分层裁切；比 Live2D 便宜、可控。
- 代码落点：`lib/screens/companion/live_avatar/`（`live_avatar.dart`、`emotion.dart`、`blink.dart`），`CompanionState` 增加 `mood` 与 `scene`。

### 5.2 Ears + Mouth：语音

- **第一阶段（push-to-talk）**：按住说话 → 端侧 STT（Flutter `speech_to_text`，iOS/Android 系统识别，中文）→ 走现有 `/v1/ai/chat`。
- **第二阶段（流式）**：服务端接 DashScope Paraformer 实时识别（WebSocket）+ CosyVoice 流式 TTS；客户端用 `just_audio` 边收边播。
- 打断：她说话时你按住说话 → 立即停 TTS、清空播放队列，进入聆听。
- 计费：语音按秒/分钟计喜点（TTS 成本），文字仍 1 喜点/轮；免费层给每日语音额度。
- 身份：首次通话播放一句「我是 AI 伴侣，用的是合成的语音」。
- 代码落点：`lib/screens/companion/voice/`（`tts_player.dart`、`stt_controller.dart`），后端 `internal/companion/voice.go` 代理 TTS/ASR（key 不进客户端）。

### 5.3 Memory：她记得

- 数据表（新增迁移）：
  - `companion_memories(user_id, kind, content, source_msg, confidence, created_at, last_used_at)`
  - `companion_summaries(user_id, period, summary, created_at)`
- 抽取：每 8–12 轮或会话结束，后台 LLM 抽 0–3 条「事实 / 偏好 / 约定 / 情绪片段」；不推断敏感信息（健康、性取向、财务细节）。
- 检索：首版按时间衰减 + 关键词；二期加 embedding（pgvector），每轮注入 top 5（≤ 400 字）。
- 可见可删：「看她 → 她记得的事」列出全部记忆，可逐条删除；删除后服务端与本地缓存同步清除。
- 巩固（Airi 的 Memory Alaya）：每天凌晨把当天碎片合并成一段；「她昨晚想起的三件事」可以在第二天自然提起。
- 代码落点：后端 `internal/companion/memory.go` + scheduler job；客户端 `memory_screen.dart`。

### 5.4 Brain：情绪标签与主动排程

- `/v1/ai/chat` 的 companion 回复增加结构化尾部（或 SSE 事件）`{"emotion":"shy","energy":0.6}`，客户端只用于表现，不展示。
- 主动消息从「本机模板」升级为「服务端排程」：用户作息、上次话题、记忆、节日/周末 → 生成候选消息；推送走现有 pusher；频率上限 2 条/天、夜间静默、可关。
- 不做：付费亲密值、恋爱进度、连续签到奖励。

### 5.5 形象即皮肤

- 每个「遇见」形象 = 立绘层 + 声音 id + 语气 prompt + 朋友圈内容；切换时三者一起换，记忆不换。
- 资产复用：同一套骨架 + 不同发型/服装/妆容，控制包体（每套 ~300KB WebP + 分层图）。

## 六、三期路线

### P0：她会动（1–2 周）

- 分层 2D 立绘：呼吸、眨眼、视线跟随、三个情绪。
- 进场动画升级：她在房间里（背景 + 站位），点她有反应（看你 / 笑）。
- 文字回复带 emotion → 表情变化。
- 验收：不需要说话，光看着就觉得「她在」。

### P1：她会说（2–3 周）

- push-to-talk + 系统 STT；CosyVoice TTS 播放；嘴型同步；打断她。
- 语音计费与每日额度；首次语音的 AI 声明。
- 验收：一次完整的「按住说—她听完—她开口」闭环，端到端 < 2.5s。

### P2：她记得（3–4 周）

- 记忆抽取、检索、记忆页（可删）；每日巩固；主动消息服务端化 + 推送。
- 验收：隔天她主动提起昨天的事，且「她记得的事」里能查到、能删。

### P3（评估后）

- Live2D/VRM 接入（先做技术验证）；桌面宠物模式；多端同步；语音通话常驻。

## 七、成本与风险

- **TTS/ASR 成本**：按分钟计，必须设免费额度与喜点价；先 TTS 后 ASR。
- **延迟**：目标首字 < 1.2s、整句 < 2.5s；流式 TTS + 预连接。
- **包体**：分层立绘每套控制 < 1MB；表情帧用 WebP。
- **合规**：每处标明 AI；合成语音声明；不做真人冒充；记忆可查可删；未成年人保护。
- **情感依赖**：主动消息上限、夜间静默、定期提示「真实生活更重要」；不做付费亲密。

## 八、需要拍板的三件事

1. **语音优先还是立绘优先？** 我建议 P0 先立绘（便宜、立刻提升「在场感」），P1 再语音。
2. **记忆放服务端还是本机？** 我建议服务端（换机可恢复），但要提供「她记得的事」可删页。
3. **Live2D 现在就上吗？** 我建议先分层 2D，P3 再做技术验证；Live2D 的包体、插件成熟度、iOS 性能都还没验证。
